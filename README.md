핵심 흐름:

1. 사용자/AI 에이전트가 변경 사항을 push 하면 GitHub Actions Runner (`LXC 101`)가 워크플로우를 실행합니다.
2. Terraform 워크스페이스는 1Password `homelab` 볼트에서 시크릿을 주입받아 Proxmox/Cloudflare/GCP에 적용합니다.
3. `100-pve`는 모든 LXC/VM의 SSOT이며, `templates/*.tftpl`을 렌더링해 SSH로 `/opt/{service}/`에 배포합니다.
4. Traefik(LXC 102)이 인그레스를 처리하고, ELK 스택이 로그/이벤트를 수집합니다.
5. 외부 트래픽은 `https://cliproxy.jclee.me/v1` 공개 엔드포인트로 노출됩니다.

자세한 아키텍처 결정은 `docs/adr/`, 런북은 `docs/runbooks/`, 모듈 의존성은 `DEPENDENCY_MAP.md`를 참조하세요.

# English

## 1. Overview

This repository is a **Terraform monorepo** that provisions the `jclee.me` homelab and its adjacent external services. It manages a Proxmox LXC/VM fleet, networking, an observability stack, and external services (Cloudflare, GitHub, Slack, GCP) via Terraform workspaces, with 1Password secret injection and a GitHub Actions CI/CD pipeline.

- **Domain**: `jclee.me`
- **Internal subnet**: `<homelab-host>/24` (LXC/VM fleet)
- **Terraform**: `1.10.5` (`>= 1.7, < 2.0`)
- **Public endpoint**: `https://cliproxy.jclee.me/v1`
- **Workspace convention**: flat `NNN-SVC`
  - `1–255` = internal infra (Proxmox LXC/VM, e.g. `<homelab-host>`)
  - `300+` = external services (Cloudflare, GitHub, Slack, etc.)
  - `400+` = public cloud (GCP, etc.)
- **Core orchestrator**: `100-pve` — single source of truth for all LXC/VM lifecycle
- **Workspace count**: 21 (`80s` physical, `100s` Proxmox infra, `200s` VM apps, `300s` external, `400s` cloud)

This README centralizes the automation inventory, repository structure, local development workflow, command reference, and contribution guide.

## 2. Features

### 2.1 Infrastructure as Code

- Per-service **Terraform workspaces** (e.g. `105-elk/terraform/`, `112-mcphub/`, `300-cloudflare/`)
- Flat `NNN-SVC` directory convention plus short aliases in the `Makefile` (`pve`, `elk`, `mcphub`, `cloudflare`, …)
- `templates/*.tftpl` → rendered config pipeline (`config-renderer` module)
- `remote_state` for inter-tier dependencies
- Local backend with `.tfstate` committed to git; CI concurrency groups serialize applies

### 2.2 Secret Management

- **1Password** `homelab` vault (12 items, 48 keys)
- Standardized injection via `modules/shared/onepassword-secrets/`
- **Zero plaintext secrets** in the repository — all credentials are sourced from 1Password

### 2.3 Automation (CI/CD)

- 14 GitHub Actions workflows (branch/PR/release/health/docs)
- [qodo-ai/pr-agent](https://github.com/qodo-ai/pr-agent) AI review
- Dependabot auto-merge, merged-PR cleanup
- CI failure → issue auto-creation, release notes automation
- README auto-generation/sync (target: `https://bot.jclee.me`)

### 2.4 Observability

- ELK stack (`105-elk/`) — Filebeat → Logstash → Elasticsearch + ILM
- Filebeat collection from every container/service
- Logstash pipeline templated via `templates/logstash.conf.tftpl`

### 2.5 External Service Integrations

- **Cloudflare** (`300-cloudflare/`): DNS, Access, Tunnel, Logpush, Identity Provider
- **GitHub** (`301-github/`): repository/team/permission management
- **Slack** (`320-slack/`): notifications and webhooks
- **GCP** (`400-gcp/`): public cloud resources

```mermaid
  CF --> Traefik["Traefik<br/>Ingress LXC 102"]
  Traefik --> Fleet
  Fleet --> Public["Public Endpoint<br/>https://cliproxy.jclee.me/v1"]
```

End-to-end flow:

1. A user or AI agent pushes a change; the GitHub Actions Runner (LXC 101) executes the workflows.
2. Terraform workspaces pull secrets from the 1Password `homelab` vault and apply to Proxmox/Cloudflare/GCP.
3. `100-pve` is the SSOT for all LXC/VM lifecycle and renders `templates/*.tftpl`, deploying them via SSH to `/opt/{service}/`.
4. Traefik (LXC 102) handles ingress; the ELK stack ingests logs and events.
5. Public traffic is exposed at `https://cliproxy.jclee.me/v1`.

For deeper context see `docs/adr/` (decisions), `docs/runbooks/` (ops), and `DEPENDENCY_MAP.md` (module graph).

## 9. Contribution Guide

### 9.1 Branch Strategy

- `master`: always deployable.
- `NNN-short-name`: feature/bugfix branch.
- `issue/NNN-slug`: issue-driven work (auto-generated by `02_issue-to-branch.yml`).
- `bot/...`: bot-generated branches.

### 9.2 PR Workflow

1. Create a branch (`02_issue-to-branch.yml` or manual).
2. Push → a PR is opened automatically (`01_branch-to-pr.yml`).
3. `10_pr-review.yml` posts an AI review via [qodo-ai/pr-agent](https://github.com/qodo-ai/pr-agent).
4. `11_security-pr-review.yml` runs security checks.
5. When labels/checks pass, `13_pr-auto-merge.yml` merges the PR.
6. Dependabot PRs are handled by `12_dependabot-auto-merge.yml` per policy.
7. `15_merged-pr-cleanup.yml` cleans up branches/comments post-merge.

### 9.3 Commit Conventions

- Clear, intent-driven messages (English or Korean).
- Keep changes to the `100-pve` SSOT (`envs/prod/hosts.tf`) in a single commit.
- When you edit a `templates/*.tftpl`, the rendered `configs/` is regenerated in CI.

### 9.4 Security

- **Never** commit secrets outside 1Password — Gitleaks will block the push.
- Responsibilities are declared in `OWNERS` / `OWNERS_ALIASES`.
- CI failures are auto-issued by `37_ci-failure-issues.yml`.

### 9.5 Documentation

- `AGENTS.md`: auto-generated project knowledge base (refreshed on push).
- `ARCHITECTURE.md`: architecture reference.
- `CODE_STYLE.md`: naming / file org / variable / template conventions.
- `DEPENDENCY_MAP.md`: module dependency graph + template inventory.
- `docs/adr/`: ADRs (append-only; supersede with a new ADR).
- `docs/runbooks/`: operational runbooks.
