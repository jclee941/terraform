## 4. jclee-bot 자동화 영역

> **핵심 원칙**: 저장소에 가하는 모든 변형(mutating) 자동화는 **`jclee-bot`** GitHub App 신원 하나로 소유·서명됩니다. 사람/외부 봇은 동일 영역에 직접 쓰기 작업을 하지 않습니다.

### 4.1 소유 표면 (App-owned)

jclee-bot이 **소유**하는 변형 자동화 영역은 다음과 같습니다.

- **PR 라이프사이클**
  - 브랜치에서 PR 자동 생성 / PR-to-branch 동기화
  - 자동 리뷰, 자동 라벨링, 자동 머지 (의존성 업데이트 포함)
  - 머지된 PR 정리(원격 브랜치 삭제, 상태 종료)
- **이슈 라이프사이클**
  - `jclee-bot에의해자동화됨` — 신규/기존 이슈 자동 분류, 백필, 자동 트리아지
  - CI 실패 → 이슈 자동 생성, 종료 조건에 따라 자동 close
  - 릴리스 노트 생성 및 게시
- **다운스트림 헬스체크**
  - 배포된 워크스페이스의 상태 점검 및 비정상 시 자동 이슈 발행
- **보안 자동 픽스**
  - Gitleaks/CodeQL/Dependabot 결과에 대한 자동 PR 생성

### 4.2 사람/외부 협업 영역 (App does NOT mutate)

- 코드 리뷰 자체의 컨텐츠(사람이 작성)
- `qodo-ai/pr-agent`가 남기는 리뷰 코멘트(읽기 전용)
- Dependabot이 의존성 업데이트 PR을 **여는** 행위(jclee-bot이 머지를 **소유**)

### 4.3 CI 트리거와 소유의 분리

`.github/workflows/`에는 14개의 워크플로우가 존재하며, 이는 **구현 트리거**일 뿐 자동화의 진실의 원천(source of truth)이 아닙니다. 동일한 트리거가 다른 App 신원으로 실행되면 실패하도록 보호 규칙이 적용되어 있습니다.

# English

## 1. Overview

This repository is an **Infrastructure-as-Code monorepo** for managing the `jclee.me` homelab and related external services. It provisions Proxmox LXC/VM fleets, internal DNS, the ELK observability stack, the MCP hub, and external services (Cloudflare) through **Terraform workspaces**, with full automation via 1Password secret injection and GitHub Actions CI/CD.

- **Domain**: `jclee.me`
- **Internal subnet**: `<homelab-host>/24` (RFC1918, must never be published)
- **Workspace convention**: `NNN-SVC` (e.g. `103-coredns`, `105-elk`, `112-mcphub`, `300-cloudflare`)
- **State backend**: local (`.tfstate` committed)
- **Public endpoint**: <https://cliproxy.jclee.me/v1>
- **Docs mirror**: <https://bot.jclee.me>

## 2. Features

- **Central orchestrator (`100-pve`)** — single source of truth for all LXC/VM lifecycle
- **Template pipeline** — `hosts.tf → module.hosts → onepassword_secrets + config_renderer → *.tftpl → /opt/{service}/`
- **1Password secret injection** — runtime secret delivery via the `onepassword-secrets` module
- **Traefik ingress** — LXC 102 routing, paired with Cloudflare Tunnel
- **ELK observability** — Filebeat → Logstash → Elasticsearch with ILM
- **MCP hub** — `112-mcphub` unifies multiple MCP servers
- **Cloudflare integration** — declarative DNS / Access / Tunnel / Logpush
- **PR automation** — `qodo-ai/pr-agent` review + Dependabot auto-merge
- **Security scanning** — CodeQL, Gitleaks, Dependency Review, OpenSSF Scorecard

## 4. jclee-bot automation surfaces

> **Core principle**: every **mutating** automation touching this repository is owned and signed by a single GitHub App identity: **`jclee-bot`**. Humans and other bots do not perform direct write operations in the same surfaces.

### 4.1 App-owned surfaces

`jclee-bot` **owns** the following mutating surfaces:

- **PR lifecycle**
  - Branch-to-PR automation, PR-to-branch sync
  - Auto review, auto labeling, auto merge (including dependency updates)
  - Merged-PR cleanup (remote branch deletion, status closure)
- **Issue lifecycle**
  - `jclee-bot에의해자동화됨` — auto classification, backfill, and triage of new/existing issues
  - CI failures → automatic issue creation; auto-close on resolved conditions
  - Release-note generation and publishing
- **Downstream health checks**
  - Post-deploy state checks on applied workspaces; auto-issue on anomalies
- **Security auto-fix**
  - Auto PRs for Gitleaks/CodeQL/Dependabot findings

### 4.2 Human / external collaboration surfaces (App does NOT mutate)

- The content of code reviews (humans)
- Comments posted by `qodo-ai/pr-agent` (read-only)
- Dependabot **opening** dependency-update PRs (jclee-bot **owns** the merge step)

### 4.3 Trigger vs ownership

There are 14 GitHub Actions workflows under `.github/workflows/`. They are **implementation triggers**, not the source of truth for automation. Guard rails ensure that the same trigger executed under a different App identity fails closed.

## 5. Go tools

This repository currently has **0 cross-workspace Go automation tools** at the top level. All mutating automation is performed through GitHub Actions with `jclee-bot` authority.

Workspace-internal **operational** Go helpers do exist. They run only inside the relevant workspace container lifecycle and are **not** externally visible automation surfaces.

- `105-elk/scripts/`
  - `setup-ilm.go` — Elasticsearch ILM policy bootstrap
  - `setup-watcher.go` — Watcher registration/refresh
  - `remove-promtail.go` — Promtail cleanup utility
- `112-mcphub/config/entrypoint-patch.go` — MCP hub entrypoint patcher

> New cross-workspace tools must live under `scripts/` (when created) or a dedicated module, and must be registered in the `Makefile` plus the "Automation Surfaces" section of [`ARCHITECTURE.md`](./ARCHITECTURE.md).

## 6. Quick start

### 6.1 Prerequisites

- Terraform `1.10.5` (`>= 1.7, < 2.0`)
- `op` (1Password CLI) signed in
- Proxmox API token (from 1Password `homelab` vault)
- GitHub App: `jclee-bot` installed with repository permissions

### 6.2 Standard flow

1. Create a branch — `jclee-bot` generates branches from template issues
2. Commit changes
3. Open a PR — `qodo-ai/pr-agent` performs auto review
4. CI passes — CodeQL · Gitleaks · Terraform plan/validate
5. Auto merge — `jclee-bot` merges per dependency/type policy
6. Deploy — `100-pve` then downstream workspaces, automatically
7. Cleanup — `jclee-bot` removes the merged remote branch

## 9. Contribution guide

1. **Read the conventions** — [`CODE_STYLE.md`](./CODE_STYLE.md), [`ARCHITECTURE.md`](./ARCHITECTURE.md)
2. **Issue-first** — new branches originate from issues (the `jclee-bot에의해자동화됨` flow)
3. **Use templates** — new services go under `NNN-SVC/` with `templates/*.tftpl` and `terraform/`
4. **Reuse modules** — Proxmox resources via `modules/proxmox/{lxc,vm,lxc-config,vm-config,config-renderer}`
5. **Secrets live in 1Password** — never commit plaintext (route through `modules/shared/onepassword-secrets`)
6. **Accept PR automation** — review and adopt `qodo-ai/pr-agent` suggestions
7. **Verify post-merge cleanup** — `jclee-bot` removes remote branches; remove local ones manually

See [`CONTRIBUTING.md`](./CONTRIBUTING.md) for full rules.
