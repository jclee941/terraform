## 4. jclee-bot 자동화 영역

**jclee-bot**은 본 저장소의 모든 변형(mutating) 자동화를 소유합니다. 14개의 GitHub Actions 워크플로는 *구현 트리거*일 뿐, 자동화의 진실 공급원(source of truth)은 **jclee-bot**입니다. 아래 영역은 워크플로 파일을 직접 나열하지 않고, jclee-bot이 책임지는 *기능 표면*을 기준으로 정리합니다.

### 4.1 읽기 전용 트리거 (Read-only)

- **CI 빌드**: push/PR 시 정적 분석, 린트, 테스트를 트리거. 외부 변형 없음.

### 4.2 변형 자동화 (Mutating) — jclee-bot 소유

- **Pull Request 자동화**
  - 브랜치 → PR 핸드오프 (원격 브랜치를 PR로 승격)
  - AI 리뷰 트리거 ([qodo-ai/pr-agent](https://github.com/qodo-ai/pr-agent))
  - 보안 특화 PR 리뷰 (CodeQL / Gitleaks 결과 반영)
  - Dependabot PR 자동 머지 (호환 버전으로 판단될 때)
  - 신뢰 라벨이 부착된 PR 자동 머지
  - 리뷰 피드백에 대한 봇 자동 수정 PR
  - 머지된 PR의 잔여 정리 (이슈 링크, 브랜치 삭제, 알림)
- **Issue 자동화**
  - 이슈 → 브랜치 자동 생성 (이슈 본문이 작업 명세로 변환됨)
  - 이슈 백필(backfill) — 닫힌 이슈에 누락된 메타데이터 보강
  - **CI 실패 → 이슈 자동 생성**: 실패 워크플로에서 파생된 자동 생성 이슈는 닫힐 때 `jclee-bot에의해자동화됨` 마커를 댓글에 부착하여 봇이 시작한 상태 전이를 명확히 표시합니다.
- **릴리스 자동화**
  - 릴리스 노트 자동 생성 (변경 로그, 워크스페이스 영향도)
  - 릴리스 게시 (태그, GitHub Release, 공지)
- **운영 헬스체크**
  - 다운스트림 헬스체크 — 외부 의존(Cloudflare, GitHub API, OAuth IdP) 장애를 감지하면 자동 이슈를 발행.

### 4.3 안전성 보장

- 변형 자동화는 모두 `jclee-bot` GitHub App을 통해 발생하며, 사람 리뷰어의 라벨/승인 없이는 머지·릴리스·삭제 단계에 진입하지 않습니다.
- 워크플로는 *트리거*일 뿐 결정 로직은 봇에 있으므로, 봇의 정책이 바뀌면 14개 트리거를 한꺼번에 수정할 필요가 없습니다.

## 5. Go 도구

# English

## 1. Overview

This repository is an **Infrastructure-as-Code monorepo** that provisions the `jclee.me` homelab and its adjacent external services. It manages the Proxmox LXC/VM fleet, networking, the monitoring stack, and external surfaces (Cloudflare, GitHub, Slack) as Terraform workspaces, with 1Password-injected secrets and a GitHub Actions-based CI/CD pipeline owned end-to-end by **jclee-bot**.

- **Domain**: `jclee.me`
- **Internal subnet**: `<homelab-host>/24` (LXC/VM fleet; RFC1918, never exposed)
- **Terraform**: `1.10.5` (`>= 1.7, < 2.0`)
- **Public endpoint**: <https://cliproxy.jclee.me/v1>
- **Workspace convention**: flat `NNN-SVC`
  - `1–255` — internal infra (Proxmox LXC/VM)
  - `300+` — external services (Cloudflare, GitHub, Slack, …)
  - `400+` — public cloud (GCP)
- **Modules**: `modules/proxmox/{lxc, vm, lxc-config, vm-config, config-renderer}`, `modules/shared/onepassword-secrets`
- **Total workspaces**: 21 (Tier 0/1/independent/template-only)

## 2. Features

- **Single Source of Truth**: `100-pve/envs/prod/hosts.tf` owns every host IP, VMID, role, and port.
- **Template rendering pipeline**: `{NNN}-{svc}/templates/*.tftpl` → `config-renderer` module → `configs/` → SSH deploy.
- **1Password secret injection**: `modules/shared/onepassword-secrets` exposes the `homelab` vault (12 items, 48 keys).
- **Parallel, safe applies**: Tier 1 workspaces depend on Tier 0's `remote_state`; GitHub Actions concurrency groups serialize writes.
- **Local state backend + Git commits**: `.tfstate` is committed for change tracking.
- **Automated security scanning**: CodeQL, Gitleaks, Dependency Review, OpenSSF Scorecard.
- **AI-assisted PR review**: [qodo-ai/pr-agent](https://github.com/qodo-ai/pr-agent) integration.
- **jclee-bot automation**: end-to-end GitHub Actions automation covering issue → branch → PR → merge → release.

## 4. jclee-bot Automation Surfaces

**jclee-bot** owns every mutating automation in this repository. The 14 GitHub Actions workflows are *implementation triggers*; the source of truth for automation policy is **jclee-bot** itself. The surfaces below are organized by *function*, not by individual workflow file.

### 4.1 Read-only triggers

- **CI build** — static analysis, lint, tests on push/PR. No external mutations.

### 4.2 Mutating automation (jclee-bot owned)

- **Pull Request automation**
  - Branch-to-PR handoff (promote remote branches into PRs)
  - AI review via [qodo-ai/pr-agent](https://github.com/qodo-ai/pr-agent)
  - Security-focused PR review (ingests CodeQL / Gitleaks results)
  - Dependabot auto-merge for compatible-version PRs
  - Auto-merge for PRs bearing a trusted label
  - Bot auto-fix PRs in response to review feedback
  - Merged-PR cleanup (issue linking, branch deletion, notifications)
- **Issue automation**
  - Issue → branch (issue bodies are translated into work specs)
  - Issue backfill (retrofit missing metadata on closed issues)

## 9. Contribution Guide

1. **Issues first** — every change starts from an issue. Fill in the templates so jclee-bot can derive a branch from it.
2. **Respect the SSoT** — host IPs/resources live in `100-pve/envs/prod/hosts.tf` only. Never hardcode elsewhere.
3. **Templates first** — service config goes in `{svc}/templates/*.tftpl`; `config-renderer` does the rendering.
4. **Secrets belong to 1Password** — never commit plaintext secrets; inject via `modules/shared/onepassword-secrets`.
5. **PR label policy**
   - `auto-merge` — jclee-bot will merge if deemed safe
   - `needs-review` — human reviewer required
   - `breaking` — may cause downtime or data migration
6. **Don't depend on automation** — workflows must remain verifiable by a human via `make plan` / `make verify` even if jclee-bot is offline.
7. **Update docs together** — if behavior changes, update `ARCHITECTURE.md`, `DEPENDENCY_MAP.md`, and `AGENTS.md` in the same PR.
8. **Authoritative conventions** — see [`CODE_STYLE.md`](./CODE_STYLE.md) · [`CONTRIBUTING.md`](./CONTRIBUTING.md) · [`ARCHITECTURE.md`](./ARCHITECTURE.md).
